Продолжи работу над проектом FastDrop PS4 в репозитории PS4-share (ветка main). Ничего не пропусти из требований и текущего состояния проекта.

1. Главная цель проекта:
- Нативное homebrew-приложение (.pkg) для PS4 на OpenOrbis PS4 Toolchain для быстрой двусторонней передачи файлов между PS4 и смартфоном (цель 20+ MB/s по LAN/5GHz Wi-Fi или прямому кабелю/адаптеру со статическими IP, без лишнего софта).
- На текущем этапе нужен рабочий каркас/макет (stub) .pkg с тёмно-зелёным дизайном (тёмный фон, гармоничные зелёные акценты/текст), где уже отображаются и интерактивно переключаются элементы интерфейса (кнопки «Отправить» и «Принять», история передач, настройки и папки сохранения, быстрый выбор), но пока без финальной реальной передачи файлов/установки.
- В итоговой логике: автосортировка входящих файлов по расширению (.pkg -> установка через RPI или сохранение в папку в зависимости от выбранного режима; .prx -> папка плагинов GoldHEN; остальные файлы -> пользовательская папка сохранения).

2. Что уже сделано в репозитории (PS4-share, ветка main):
- Создана структура каталогов: `.github/workflows/build-ps4-pkg.yml` и `ps4_fastdrop/` (`source/main.c`, `Makefile`, `FastDropPS4.gp4`, а также `ps4_fastdrop/setup_toolchain.sh` для загрузки и распаковки OpenOrbis PS4 Toolchain).
- Настроен GitHub Actions workflow (`Build PS4 FastDrop Stub PKG`), который ставит зависимости, скачивает и распаковывает OpenOrbis PS4 Toolchain (`OO_PS4_TOOLCHAIN`), готовит `icon0.png` и `param.sfo`, компилирует ELF/eboot.bin, собирает `.pkg` и загружает артефакт.

3. Текущая проблема и ближайшие шаги:
- Скачивание и распаковка OpenOrbis PS4 Toolchain в GitHub Actions уже работают.
- При компиляции `ps4_fastdrop/source/main.c` возникла ошибка: `use of undeclared identifier 'ORBIS_SYSMODULE_USER_SERVICE'` и `use of undeclared identifier 'ORBIS_SYSMODULE_PAD'`. Нужно убрать вызовы `sceSysmoduleLoadModule` с этими несуществующими константами (так как `SceUserService` и `ScePad` линкуются напрямую через `-lSceUserService -lScePad`), оставив `sceUserServiceInitialize(NULL);` и `scePadInit();`.
- После исправления `main.c` нужно довести сборку `.pkg` в GitHub Actions до зелёного статуса и получения готового артефакта `.pkg`, затем развивать интерфейс и реальную сетевую/файловую/RPI логику.
